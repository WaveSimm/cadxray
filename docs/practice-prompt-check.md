### 프롬프트 길이와 무관한 발견 (문서·툴 결함)
1. **build_features 의 rect/circles 는 Block 제약** — 스케치 폭·높이·구멍 위치가 Params 에 묶이지 않는다. 배포된 `01-plate-done.FCStd` 를 열어 보니 SketchPad 수식 0개, SketchPocket 은 hole_d 만 4개. **Params.width/height/margin 은 아무것도 참조하지 않는다.**
   - 문서 2단계 «스케치와 Pad 가 그 셀을 참조» → 실제로는 Pad.Length 만 참조.
   - 문서 5단계 «margin 을 12 로 바꾸고 재계산» → 배포 파일로는 구멍이 안 움직인다.
   - 이번 검증에서는 AI 가 execute_code 로 DistanceX/Y 제약 + 수식을 직접 걸어 통과시켰다. 툴을 고치거나(rect/circles 에 expr 지원) 문서를 «두께만 파라메트릭»으로 바꿔야 한다.
2. Spreadsheet 는 Body 안에 못 들어간다(`Body: object is not allowed`). 문서의 트리 표기 «Body › Params, Sketch, Pad» 는 «Params, Body › Sketch, Pad» 가 맞다.
3. 스케치 이름: build_features 는 SketchPad/SketchPocket, 문서 표는 Sketch/Sketch001. 둘 중 하나로 통일.
4. 테스트 중 문서 p01_plate 가 한 번 사라짐(원인 미확인 — FreeCAD 쪽에서 닫힌 듯). 재생성 후 정상.

### 프롬프트 길이와 무관한 발견
5. **동시 호출 실패 (크래시 아님)**: get_document_graph + get_sketch_diagnostics×2 + suggest_sketch_fixes 를 동시에 보내자 뒤 3개가 "연결할 수 없습니다" 로 실패하고 FreeCAD 가 재시작된 상태(프로세스 시작 21:04:38, 문서 0개)였다. 사용자가 그 시점에 FreeCAD 를 직접 닫았다 열었다고 확인 → 크래시가 아니라 재시작과 겹친 것. 동시 요청이 안전한지는 별도 확인 필요(이번 검증은 이후 직렬 호출).
6. **apply_sketch_fixes 묶음 적용 버그**: Sk_Fixes 추천 [1,2,3,4,5,8] → "중복 제약 14번" 으로 되돌려짐. [1,2,3,4,5] 적용 후 원 같음(구 8번)만 따로 적용하면 성공. 같은 제약이 묶음에서만 중복으로 판정 → 묶음 적용 시 인덱스/평가 순서 문제로 추정. 문서 8번 프롬프트(「추천된 것만 적용」)가 그대로는 실패한다.
7. `recommended` 에 사각형 변끼리 「길이 같음」(Line1=Line3, Line1=Line4) 이 들어감 — 수평·수직+일치 제약과 중복이라 함께 적용하면 redundant. 후보 평가가 개별이라 묶음 효과를 못 본다.
8. suggest_sketch_fixes(Sk_Conflict) 는 문서 예시(후보 2개)와 달리 4개(add_equal 2개가 앞에). add_equal 2개는 effect 가 여전히 과구속이라 무의미 — 필터링하거나 뒤로 보내야 한다. 문서의 «2번으로 해 줘» 는 실제 id 4.
9. apply_sketch_fixes 가 재계산까지 하므로 그 뒤 tracked_recompute 는 resolved=[] — 문서 «재계산 추적에 '해결됨: Pad'» 기준은 apply 응답의 recompute.invalid_objects=[] 로 바꿔야 한다.
10-a. (동시 호출 재검증) 실습 7 에서 analyze_shape + find_holes + make_drawing 을 동시에 보내 전부 성공 → 동시 호출은 문제없음. 5번 항목은 사용자 재시작과 겹친 것으로 확정.

### 프롬프트 길이와 무관한 발견
15. **문서 기대 «5종 모두 잡힘» 이 툴 임계값과 안 맞는다.** 70° 면(수직에서 20°)은 한계 45° 안이라 오버행이 아니고, Ø3 은 min_hole 2.0 보다 커서 작은 구멍이 아니다. 실제 3종. 문서 본문의 «점수 41» 과 그림 설명 «점수 76, 문제 4종» 도 서로 다르다(실측 85). 문서의 PETG 오버행 한계 «50°» 도 툴 표는 45°.
16. **apply_print_fixes 묶음에서 면 번호가 밀린다.** thicken 이 먼저 피처를 추가하면 뒤의 overhang_chamfer 의 Face17 이 다른 면이 되어 건너뛴다. 면 이름 대신 점(point) 으로 다시 찾거나, chamfer 를 먼저 적용해야 한다.
17. **눈물방울을 적용해도 수평 구멍 문제가 계속 잡힌다**(through: null). 검사가 눈물방울 유무를 모른다. 게다가 눈물방울의 45° 면이 «한계 45°» 에 걸려 새 오버행(84 mm²)으로 잡힌다 — 비교는 `>` 가 아니라 `>=` 인 듯. 문서 «수평 구멍 문제가 사라져야» 기준이 성립하지 않는다.
18. thicken 이 Face12 를 조용히 건너뛴다(applied 에 Face11 만, skipped 에도 없음). 문서는 «건너뜀 정상» 이라 하지만 응답에 표시가 없다.
19. 방향 후보는 문서 «7개» 가 아니라 6개(현재 포함). 점수가 101.7 처럼 100 을 넘는다.

### 프롬프트 길이와 무관한 발견
20. **PETG 표 값 불일치**: 툴 E 2,000 / 항복 45, 문서 «E 2,100 / 항복 50». 그래서 두께 7 로는 안전율 1.81 — 문서 «≥ 2, ok» 가 안 나온다. suggest_reinforcement 도 «굽힘이면 7.25 mm» 라고 하므로 문서 6단계를 «두께 8» 로 바꾸거나 표를 맞춰야 한다.
22. (case.pdf 어셈블리 시험 중) **build_features 의 `profile.wires` 설명이 틀리다.** 툴 설명은 `{"wires": [[...], ...]}` 인데 핸들러(rebuild.py 1080)는 각 wire 를 section_profile 의 element dict 목록으로 기대해 점 목록을 주면 `'list' object has no attribute 'get'`. 점 목록 여러 개(링 홈 등)는 `polygons` 를 써야 한다 — 설명에 `polygons` 가 빠져 있다.

21. 두께 변경은 Pad.Length 직접 수정(실습 1 의 Params 가 없으면). 문서 «두께 파라미터(또는 Pad 길이)» 그대로.

10. 연습 스케치 생성 시 벌어짐을 Vertical 제약이 있는 변에 넣으면 솔버가 닫아 버린다(Pad 가 Valid). 1번 프롬프트에 «벌어진 꼭짓점 쪽 변은 수직/수평 제약 없이» 를 넣거나 AI 워크플로에 적어야 재현된다.
